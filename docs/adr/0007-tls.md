# ADR-0007: TLS termination at a reverse proxy in front of the gateway

- **Status:** Accepted
- **Date:** 2026-07-15
- **Deciders:** Platform team

## Context

The gateway today speaks plain HTTP. The browser-facing frontend
(`https://app.example.com` in production) calls the gateway at
`http://gateway.internal:3000/api/v1` over the cluster network —
plaintext. The same is true for any operator hitting
`http://localhost:3000/docs` from a coffee shop.

This is unacceptable for three reasons:

1. **Confidentiality.** JWTs in `Authorization` headers and any
   personally identifiable information in request bodies traverse
   the network unencrypted.
2. **Integrity.** Without TLS an on-path attacker can mutate
   responses or inject requests.
3. **Compliance.** PCI DSS requires TLS for any traffic that touches
   cardholder data — and our payment service sits behind the
   gateway.

We also need a single, well-known place to manage certificates so
that rotation doesn't touch ten different service configurations.

## Decision

We terminate TLS at a **reverse proxy** that sits in front of the
gateway. The proxy is the only ingress the public internet can reach.
The gateway and downstream services continue to speak HTTP on a
private network.

### Proxy choice

- **Local / dev / Compose:** Caddy (single binary, automatic
  certificate issuance via the internal CA, zero config).
- **Production:** a managed reverse proxy — either AWS ALB with
  ACM-issued certificates, Cloudflare in front, or nginx + certbot
  on a VM. The exact choice is deferred to the infrastructure
  ticket; this ADR only fixes the **boundary**.

### Topology

```
Internet
   │  HTTPS :443
   ▼
[ Reverse proxy ]  ─── TLS termination, header injection
   │  HTTP (private network)
   ▼
[ Gateway :3000 ]
   │
   ▼
[ Services :3001–3009 ]
```

### Headers the proxy must set / preserve

For the gateway to behave correctly:

- `X-Forwarded-Proto: https` — so Express' `trust proxy` setting
  reports the correct scheme in logs and redirects.
- `X-Forwarded-For` — appended, not overwritten.
- `Host` — preserved (Caddy / ALB do this by default).

For client behaviour:

- `Strict-Transport-Security: max-age=31536000; includeSubDomains;
  preload` — set by the proxy.
- `X-Content-Type-Options: nosniff`, `Referrer-Policy:
  strict-origin-when-cross-origin`, `X-Frame-Options: DENY` — set
  by the proxy.

HSTS preload submission is a follow-up after we have 30 days of
clean HSTS headers in production.

### Certificate management

- Certificates are issued by the reverse proxy from ACME (Let's
  Encrypt or the cloud provider's CA). Renewal is automatic.
- We do **not** store certificates in the application containers.
- A `tls/` volume is mounted into Caddy in Compose to simulate a
  managed cert in dev; in production this volume does not exist.

### Gateway-side changes

- `app.set('trust proxy', 1)` (already enabled) — the gateway
  trusts the first proxy hop.
- Healthcheck continues to be HTTP `/health` on the cluster
  network. The proxy is responsible for TLS health, not the
  application.
- CORS configuration is unchanged; the browser still talks to the
  same origin (the proxy host).

### Webhooks

The Stripe webhook endpoint is reached by Stripe over the public
internet, so it benefits from the same TLS termination. The
`STRIPE_WEBHOOK_SECRET` is unaffected — the HMAC is computed over
the body and is independent of the transport.

## Consequences

**Positive**

- One place to manage certificates and TLS configuration.
- The application stays portable (no certificate mounts in Compose
  services, no `https.createServer` boilerplate per service).
- HSTS and security headers can be set centrally and audited.
- The gateway remains trivially testable over plain HTTP on the
  private network — no TLS in unit tests.

**Negative / costs**

- We add a network hop. For our scale this is negligible
  (<1ms latency).
- Misconfigured `trust proxy` could expose the original client IP
  wrongness. The single proxy hop is configured explicitly.
- We must operate the proxy — renewal, monitoring, log shipping.
  This is the cost of doing TLS properly.

**Follow-ups**

- Configure the production proxy choice in the infra ticket
  referenced in `docs/RUNBOOK.md#open-production-gaps`.
- Set up a `tls_renewal_due` metric once ADR-0005 lands.
- Submit the production domain to the HSTS preload list after a
  one-month soak.
- Add a CSP header at the proxy for the frontend origin.
